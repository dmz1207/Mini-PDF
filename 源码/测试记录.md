## Added performance coverage

Thirty assertions check shared immutable input bytes and mapping lifetime; worker full-quality tiles at four rotations; progressive render equality at four rotations; queued jobs with UI timer activity; worker-count bounds; changed-document snapshots and undo; invalid-page errors and subsequent recovery; terminated-worker recovery; document closure with queued input still alive; unchanged-layout and zoom-revisit cache reuse; high-zoom tile bounds; and shutdown without remaining owned workers.

The renderer uses separate PDFium processes to respect its threading rule. Shared input avoids long-lived pinned managed byte arrays; mapped output avoids explicit per-page pixel copies. Visible jobs precede prefetch. This is bounded concurrency, with additional runtime/parser memory and cooperative first-page timing, as described in [Performance](Performance.md). Search, edits, serialization and printing are not all asynchronous.

A separate baseline/current benchmark checks eight pixel SHA-256 values for full pages and tiles at four rotations. All match. Timings include unchanged cached layout, page-size lookup, render/serialize, shared-resource merging and warmed sequential/parallel rendering. The full table retains operations that were slightly slower in one run. Benchmark comparisons are not added to the 764 regression count.

## Reproduce

Use a complete checkout, the system x64 Framework compiler and development-only pypdf, reportlab, Pillow, pymupdf and cryptography; OpenSSL is used for independent CMS verification. Set TEMP/TMP and development package caches under the project's work directory.

~~~powershell
python .\源码\verify_pdf.py fixtures .\work\tests
python .\源码\verify_features.py fixtures .\work\tests
~~~
